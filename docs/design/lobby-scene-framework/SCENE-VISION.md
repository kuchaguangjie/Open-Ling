# Ling 咨询大厅：场景说明与未来设想

状态：持续维护
首次整理：2026-07-11
适用范围：产品讨论、视觉设计、交互审查、功能规划和后续任务拆分

多 Feat 并行开发、专题地图、共同规范和文案标准见 `docs/design/spatial-experience/`。

## 1. 文档目的

咨询大厅是 Ling 新增的一套产品场景，不只是聊天页前的欢迎画面。这份文档记录它为什么存在、当前承担什么、未来可以发展成什么，以及哪些方向会破坏心理咨询应用的基本边界。

具体页面状态、热点位置、素材与响应式规则见同目录的 `README.md`。本文件优先描述长期产品意图；当实现方案变化时，应先判断产品意图是否变化，再更新具体设计。

## 2. 一句话定义

咨询大厅是用户进入 Ling 后首先抵达、可以反复返回的心理咨询工作室公共空间。它用场景、人物接待、轻度探索和自然转场，把“打开 AI 聊天窗口”转化为“来到一个地方，准备开始一次咨询”。

## 3. 为什么需要它

普通聊天产品一打开就是消息流和输入框，用户会自然把它理解为即时问答工具。心理咨询需要不同的进入节奏：先抵达、辨认环境、了解边界、选择咨询关系，再进入正式会谈。

咨询大厅主要解决五个问题：

1. **建立进入感**：让咨询从一个具体空间开始，而不是从空白输入框开始。
2. **承接准备过程**：容纳咨询师介绍、AI 使用边界、安全提示和预约选择，不挤占正式会谈空间。
3. **组织产品功能**：让来信、故事、自助资料、户外练习和设置各有符合现实逻辑的位置。
4. **降低开始压力**：用户不必一进来就立刻说出困扰，可以先看看、阅读或与助理交谈。
5. **形成长期场所记忆**：用户多次回来后，记住的是“Ling 工作室”，而不只是某个聊天页面。

## 4. 它是应用、游戏，还是互动叙事

Ling 仍然是心理支持与自我探索应用。它借用游戏和互动叙事中有效的表达方式，但不把咨询变成闯关、收集或角色养成。

可以借用：

- 固定场景带来的空间记忆；
- 人物立绘和短对白带来的在场感；
- 可发现物件带来的轻度探索；
- 环境微动、天气和声音带来的情绪氛围；
- 场景转场带来的仪式感；
- 持续更新的工作室故事带来的生命感。

不应借用：

- 等级、积分、签到奖励和连续登录压力；
- 以咨询师好感度为核心的养成关系；
- 把脆弱表达包装成任务、成就或可竞争结果；
- 为了增加时长而制造重复点击、搜集和障碍；
- 用悬念、依赖或暧昧文案诱导用户持续使用；
- 让娱乐反馈盖过风险提示和咨询边界。

判断标准不是“看起来像不像游戏”，而是：这种互动是否帮助用户更自然地进入咨询、理解选择、调节节奏，并保持自主性。

## 5. 用户在大厅中的身份

用户就是来到工作室的来访者，不需要另设玩家角色、头像小人或可操控替身。画面采用第一人称观看关系：用户面对场景、人物和物件，并通过点击与选择行动。

这样可以避免三种割裂：

- 大厅像 RPG，咨询页突然变成聊天软件；
- 用户控制一个虚构角色，却要用真实身份谈自己的经历；
- 人物移动成为无意义操作，拖慢真正的咨询入口。

NPC 可以存在，但其动作应表达“工作室正在运转”，而不是要求用户追逐或完成任务。

## 6. 当前空间语义

### 6.1 前台与任心

前台是咨询入口和信息入口。任心是年轻的咨询师助理，负责接待、介绍、预约和流程引导，不提供心理咨询、诊断或专业判断。

任心的价值不是成为需要经营关系的角色，而是降低陌生感、把复杂流程说清楚，并在用户不确定下一步时提供选择。

### 6.2 三位咨询师照片

照片代表“认识工作室中的人”。点击后应看到咨询师的专业介绍、工作方式、适合议题和当前咨询状态。这里不是角色图鉴，也不使用好感度、稀有度或能力数值。

### 6.3 前台合照

合照表达三位咨询师属于同一个工作室，并允许未来承载少量工作室故事。故事可以让人物更有生活感，但不能模糊咨询关系或把严肃咨询包装成恋爱、陪伴养成。

### 6.4 书架

书架是长期内容入口，当前承载咨询师来信和治愈小故事。未来适合加入主题阅读、工作室随笔和经过审查的心理教育内容，不适合堆放系统设置或即时工具。

### 6.5 右下资料桌

资料桌是实用信息入口，承载工作室留言、安全提醒、访客留言册和短时自助工具。右墙留言板仅作为场景装饰，不单独承担功能，避免画面裁切造成入口不可达。

### 6.6 窗景与户外花园

窗景是从“理解与表达”转向“感受与调节”的入口。户外场景未来可以承载正念呼吸、音乐、短暂停留和身体觉察，但不应变成小游戏合集。

### 6.7 设置

设置是明确的系统工具，保持独立图标入口，不需要强行伪装成场景物件。场景化不能以牺牲可发现性和操作效率为代价。

## 7. 核心体验流程

### 首次进入

```text
进入工作室
  → 任心简短接待
  → 了解这里 / 认识咨询师 / 预约咨询 / 自由看看
  → 必要时查看 AI 咨询边界与风险说明
  → 进入咨询师或咨询形式选择
  → 场景内简短开场
  → 正式咨询界面
```

### 再次进入

```text
回到工作室
  → 自由探索或点击任心
  → 继续已有咨询 / 开始新咨询 / 查看来信和资料
```

再次进入不应反复播放完整教学。大厅应从“首次引导页”自然转变为用户熟悉的应用主页。

## 8. 场景设计原则

1. **现实逻辑优先**：空间摆设和功能归属要像真实工作室，不能为了按钮数量堆门、堆桌子或制造不合理房间。
2. **咨询优先**：最短路径始终可以直接开始或继续咨询，探索不能成为必经障碍。
3. **场景仍然在场**：打开介绍、来信和资料时尽量保留大厅背景，让用户感觉是在查看工作室中的内容。
4. **低频动态**：光影、云、树叶、人物呼吸和表情可以微动，但不能抢夺注意力或制造焦虑。
5. **专业边界清楚**：文案使用“咨询、会谈、理解、探索”等表达，避免恋爱化、拟亲密化和依赖性“陪伴”叙事。
6. **入口可达**：响应式裁切不能让功能消失；边缘物件只做装饰，核心入口放在安全区域或提供稳定替代路径。
7. **允许安静**：用户可以什么都不点，在大厅停留片刻；系统不催促、不倒计时、不制造红点压力。
8. **逐层进入**：大厅、场景开场、正式咨询之间要有自然转场，但不能每次都增加冗长步骤。

## 9. 未来扩展方式

未来新增功能不应继续在墙上增加门。大厅保持一个稳定、可信的空间，通过以下方式扩展：

- **入口内部扩展**：书架可以增加新栏目，资料桌可以增加新工具，任心可以增加新的流程选择。
- **过渡场景扩展**：点击某个入口后先进入一张独立场景，再进入具体功能，不要求所有空间同时画在大厅里。
- **时间与状态变化**：天气、季节、灯光和少量摆件可以变化，但大厅结构和重要入口位置保持稳定。
- **内容更新**：咨询师来信、工作室故事、主题阅读和节气内容可以让空间持续生长。
- **角色状态更新**：咨询师偶尔出现在大厅或留下信息，但不依赖自由行走和复杂 NPC 调度。

## 10. 分阶段未来设想

### 近期：让大厅成为稳定入口

- 完成首次与再次进入的真实状态区分；
- 加入正式的首次咨询知情说明与确认；
- 完善任心对白、表情和预约流程；
- 接通继续上一次咨询与开始新咨询；
- 完善咨询师介绍、来信、故事和资料桌的空/加载/失败状态；
- 统一大厅、咨询开场和正式会谈的转场节奏。

### 中期：加入独立功能场景

- 咨询师选择或咨询形式选择的过渡场景；
- 个体咨询、主题咨询、团体咨询等不同形式的入口；
- 抽卡投射等表达工具，但明确其不是占卜或诊断；
- 花园中的正念呼吸、音乐和身体觉察；
- 咨询前状态整理与咨询后短暂回落空间；
- 咨询师来信、主题阅读和治愈故事的真实内容系统。

### 长期：形成可持续的工作室世界

- 三位咨询师之间有边界清楚的工作日常和工作室故事；
- 用户可以阅读并有限参与互动叙事，但不把自己的咨询内容自动写入公共故事；
- 根据真实咨询进程呈现阶段性空间变化，例如新来信、资料推荐或季节变化；
- 支持新的咨询师和咨询团队，而不破坏既有大厅布局；
- 建立内容审核、专业审查和危机文案复核流程；
- 评估是否需要声音、昼夜与更细的环境动态，并始终提供关闭选项。

## 11. 新功能应该放在哪里

每次准备向大厅增加功能时，按以下顺序判断：

1. 它是否与开始、继续或选择咨询直接相关？如果是，交给任心或咨询入口。
2. 它是否是需要阅读和长期保存的内容？如果是，放入书架。
3. 它是否是短时工具、提示或填写内容？如果是，放入资料桌。
4. 它是否帮助用户调节身体和注意力？如果是，放入花园或其他独立调节场景。
5. 它是否只是系统配置？如果是，留在设置中。
6. 它是否需要完整的视觉和交互空间？如果是，建立独立过渡场景，不改造大厅墙面。
7. 如果以上都不符合，应重新确认它是否真的属于咨询大厅。

## 12. 数据与隐私边界

- 大厅状态、会谈、来信和用户资料默认遵循 Ling 的本地保存原则；
- 不把真实会谈内容自动展示在大厅公共物件、NPC 对话或工作室故事中；
- 使用个性化推荐时，应说明依据并允许关闭；
- 危机风险不能只用场景对白处理，必须保留清楚、直接、可执行的现实求助提示；
- 团体咨询和用户参与故事涉及更高隐私风险，未形成独立数据与同意方案前不得仅按普通场景功能实现。

## 13. 审查清单

每次大厅相关改动进入实现或合并前，至少检查：

- 这项改动是否帮助进入咨询，而不只是增加可玩性？
- 用户能否快速跳过引导并开始或继续咨询？
- 空间摆设与功能位置是否符合现实逻辑？
- 是否出现恋爱化、养成化、依赖性或边界模糊的表达？
- 是否把心理咨询能力说得超过真实实现？
- 风险提示是否直接、严肃且不被视觉效果弱化？
- 背景、人物和热点是否共享坐标，常见窗口比例下是否可达？
- 常见窗口下，现有键盘操作、返回路径和系统减少动画设置是否仍然可用？
- 新内容是否有加载、空、失败和未来扩展状态？
- 用户关闭场景化体验后，核心功能是否仍然清楚可用？

## 14. 用可否证问题规划阶段

咨询大厅的路线不能只按“下一阶段增加哪些功能”来规划。每个阶段都应先回答一个可以被现实结果推翻的问题：如果结果不支持原假设，就收缩、调整或停止该方向，而不是继续增加内容试图挽救已经失效的前提。

### 14.1 当前阶段问题表

| 阶段 | 可否证问题 | 主要观察证据 | 如果答案是否定的 |
| --- | --- | --- | --- |
| 大厅与正式咨询闭环 | 大厅是否增加了进入咨询的阻力？ | 从启动到继续/开始咨询的操作步数、完成路径所需时间、跳过大厅的主动选择、低能量状态用户的走查反馈 | 缩短任心流程，强化直接继续咨询；必要时允许默认进入咨询室，大厅降为可选首页 |
| 咨询前开场 | 咨询前开场是否增强郑重感，而不是显得拖沓？ | 开场跳过情况、用户对“自然/郑重/重复”的主观反馈、首次与再次进入的差异体验 | 再次进入取消完整开场，只保留一句问候或直接落入正式会谈 |
| 咨询后返回 | 咨询师收尾和返回大厅是否带来余温，而不是延长结束负担？ | 用户能否顺利结束并离开、是否理解会谈已结束、返回大厅后的情绪感受、关闭或跳过收尾的需求 | 缩短收尾和转场；允许结束后直接关闭或留在咨询室，不强制返回大厅 |
| 花园练习 | 花园练习是有帮助的调节工具，还是无意义装饰？ | 使用前后的主观状态、练习后进入咨询的意愿、主动重复使用情况、未完成原因 | 保留花园作为安静场景，移除或弱化练习流程，不继续扩充练习数量 |
| 投射与表达工具 | 投射卡是否帮助用户开始表达，而不是成为娱乐抽卡？ | 卡片带入咨询的比例、用户书写是否产生有效表达、连续空抽或追求结果的行为、咨询师对内容可用性的反馈 | 冻结扩卡和抽取演出，改为用户主动选择的表达提示，必要时移出大厅 |
| 工作室故事 | 工作室故事是增加空间生命感，还是模糊咨询边界？ | 用户是否清楚故事与真实咨询的区别、是否出现角色攻略或亲密关系期待、故事是否干扰专业信任 | 降低互动程度，改为只读工作室随笔；删除暧昧、排他或养成式内容 |
| 团体咨询 | 团体咨询是否真的需要空间化？ | 多 AI 同席是否提升理解而不增加混乱、隐私边界是否能被正确理解、用户能否分辨各席位职责、受控内测的安全反馈 | 保留为结构化咨询团队能力，不制作团体房间；若安全性不足则不进入产品实现 |

### 14.2 新 feat 的必答模板

每个大厅或空间化新功能开始前先回答以下内容：

1. **要验证的问题**：这次不是“做什么”，而是准备回答什么问题？
2. **正向假设**：如果方向成立，用户体验会发生什么可观察变化？
3. **反向解释**：即使用户使用了它，还有哪些原因可能说明它并没有真正帮助咨询？
4. **最小验证**：为了回答问题，最少需要实现到什么程度？哪些内容先不做？
5. **证据来源**：使用人工走查、可用性访谈、本地状态、主动反馈或用户自愿导出的数据中的哪些证据？
6. **停止或降级条件**：出现什么结果时不再扩充，而是缩短、改成可选或删除？
7. **验证后的决定**：继续、调整、延后还是停止；决定应回写本文件的审查记录。

### 14.3 观测边界

- 不为了验证大厅引入默认云端遥测；
- 优先使用本地记录、人工走查和用户主动提供的反馈；
- 不以停留时长、点击次数或回访频率单独证明“有效”；
- “使用更多”不等于“更有帮助”，必须结合是否更容易进入咨询、表达、调节或结束；
- 每个 feat 的具体判断阈值应在开始实现前明确，不能在看到结果后临时修改标准；
- 涉及危机、团体咨询、依赖风险和真实心理效果的结论，不能只凭产品行为数据，需要专业人员参与审查。

## 15. 仍需讨论的问题

- 大厅最终是否取代咨询室成为长期默认首页，还是允许用户选择默认进入位置？
- 首次知情说明应在任心流程中完成，还是在进入具体咨询前单独呈现？
- “继续上一次咨询”应该在大厅常驻显示，还是只通过任心提供？
- 咨询形式增加后，使用统一选择场景还是多个主题入口？
- 工作室故事的参与程度到哪里为止，如何避免用户误解真实咨询关系？
- 团体咨询、投射卡片和正念练习分别需要怎样的专业说明与风险边界？
- 环境声音、天气和季节是否根据系统状态变化，还是完全由用户选择？

## 16. 维护方式

- 产品定位、空间语义或长期方向改变时，更新本文件；
- 具体布局、素材、热点、响应式和当前状态改变时，更新同目录 `README.md`；
- 确认实施的功能直接进入独立 `feat/` 分支；跨模块或存在重要取舍时再补充简洁方案；
- 尚未确认的设想保留在本文件，不直接写成已承诺路线图；
- 每个新 feat 先写可否证问题和停止条件，再拆功能任务；
- 每次重要审查在文末补充日期、结论和仍未解决的问题。

## 17. 审查记录

### 2026-07-11：第一版场景方向

- 确认咨询大厅是正式咨询前且可反复返回的长期场景；
- 确认固定视角、无用户角色、无自由移动；
- 确认不通过三扇物理房门承载未来功能；
- 确认任心、咨询师照片、书架、资料桌、合照和花园的基本语义；
- 确认游戏化服务于进入感与探索感，不改变心理咨询应用定位；
- 确认后续阶段以可否证问题驱动，不以功能数量或停留时长证明方向成立；
- 后续重点讨论首次知情说明、咨询形式选择和大厅作为长期首页的边界。
