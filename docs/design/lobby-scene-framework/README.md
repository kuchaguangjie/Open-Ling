# 等待室场景与交互框架

状态：第一阶段精修 Demo 已完成
分支：`feat/lobby-scene-framework`
执行工具：Codex
最后更新：2026-07-11

长期产品定位、场景语义、未来扩展方式与审查清单见：[咨询大厅：场景说明与未来设想](./SCENE-VISION.md)。本文件主要记录当前实现框架与已确认细节。

## 1. 设计目标

Ling 不应让用户进入应用后立刻面对普通聊天界面。正式咨询之前增加一个固定的“等待室”，让用户先进入具体、温暖、可以轻度探索的心理咨询空间，再自然过渡到咨询选择和正式会谈。

等待室不是 RPG 地图，也不是任务型游戏：

- 用户本人就是来访者，不显示用户角色；
- 用户不在场景中自由移动；
- 不在等待室墙面上设置三扇咨询室门；
- 场景以固定视角插画、点击探索、人物立绘对白和低频环境动态构成；
- 游戏化只用于增强进入感、探索感和关系感，不改变心理咨询是产品核心的定位。

## 2. 视觉基准

等待室基准图为：

`assets/runtime/lobby/waiting-room/waiting-room-baseline-v1.png`

基准图已确认的空间元素：

- 左侧大窗、室外湖景、纱帘、自然阳光与树影；
- 左后方前台，柜台正面仅出现一次 `Ling` Logo；
- 前台台面上的三位咨询师日常像素风合照；
- 后墙大型书架，以书籍和少量收纳、植物为主体；
- 左前方沙发、茶几、地毯与暖色灯具；
- 右墙三位咨询师像素头像与小名牌，程灵位于中央；
- 右墙留言板与下方心理自助资料矮柜。

后续原型不得随意改变基准图的房间布局、色调和视觉语言。交互和人物优先作为独立图层叠加。

## 3. 总体体验层次

```text
等待室场景层
  固定背景、环境动态、可点击区域、场景人物
        ↓
人物对白层
  前台或咨询师半身立绘、对白框、选择项
        ↓
局部探索层
  物件聚焦、纸面浮层、咨询师介绍、自助资料
        ↓
场景过渡层
  咨询选择场景或独立咨询室场景
        ↓
正式咨询层
  咨询师立绘、消息流、输入框、会谈状态
```

这些状态应像同一段体验逐渐展开，而不是在插画、弹窗和聊天页之间突然跳转。

## 4. 等待室状态模型

### 4.1 首次进入

1. 等待室由暗到明淡入；
2. 前台人物作为独立场景角色出现在柜台后；
3. 前台大半身立绘叠在全宽底部对白框后，短句以打字机效果逐句出现；
4. 用户点击对白状态下的屏幕任意位置、按空格或回车推进；对白期间等待室热点与设置入口全部锁定，避免误触；需要选择时，选项在暖色蒙版上的画面中央独立出现；
5. 选择“随便看看”后，人物对白层退出，回到自由探索状态。

首轮选项：

- 我想预约心理咨询；
- 请带我看看工作室；
- 我先自己看看。

需要用户选择时，选项不放进对白框，而是显示在画面中央的独立选择层。自由探索时，画面底栏常驻“咨询师的信”“预约咨询”和“系统设置”三个快捷入口，不属于对白选项。

Demo 使用 renderer 本机轻量存储记录是否已经看过完整欢迎，不新增数据库字段或 migration。第一次探索不强制先阅读完整说明；首次正式开始咨询前必须完成必要的 AI 边界与安全说明。

### 4.2 再次进入

再次进入不重复完整欢迎流程。用户直接进入自由探索状态；需要任心时可点击前台，再选择预约或重新听取工作室介绍。

### 4.3 自由探索

大厅完整呈现，底栏只常驻“咨询师的信”“预约咨询”和“系统设置”三个直接操作。鼠标或键盘聚焦场景内可交互区域时，使用轻微提亮、柔和轮廓、局部光影或光标变化提示，不在背景上永久摆放大量标签。

### 4.4 局部探索

点击物件后优先采用“场景仍然在场”的表现：

- 背景轻微压暗或柔化；
- 对应区域可做轻微视觉聚焦；
- 人物介绍使用立绘对白层；
- 资料和信件使用纸面式覆盖层；
- 关闭后回到原来的等待室状态。

### 4.5 开始咨询

等待室不通过物理房门选择咨询。用户点击前台或在首次欢迎中选择开始咨询后，由前台承接：

- 继续上一次咨询；
- 开始新的咨询；
- 选择一位咨询师；
- 我还不知道找谁。

之后进入独立的“咨询选择场景”，再进入具体咨询室。选择场景的视觉和内容在等待室交互原型确认后单独设计。

## 5. 第一版交互地图

| 区域 | 优先级 | 作用 | 表现形式 |
| --- | --- | --- | --- |
| 前台 | 核心 | 欢迎、了解 Ling、开始或继续咨询 | 前台立绘与对白选择 |
| 三位咨询师照片 | 核心 | 认识咨询师、查看介绍、预约 | 对应咨询师立绘与介绍 |
| 大书架 | 主要 | 阅读三位咨询师创作的虚构故事 | “故事簿”纸面目录 |
| 右墙留言板 | 氛围 | 保留为空间装饰，不设置独立热点 | 随场景显示 |
| 右下资料桌 | 主要 | 工作室留言、安全提醒、自助资料与访客留言册 | 统一“留言与自助资料”覆盖层 |
| 前台合照 | 探索 | 三位咨询师的日常与工作室故事 | 小照片聚焦与短故事 |
| 窗户 | 主要 | 进入湖畔花园晴天/雨天场景 | 全画幅场景转场与轻动态 |
| 沙发与茶几 | 主要 | 回看已经结束的会谈 | “会谈记录”档案覆盖层 |
| 底部快捷入口 | 工具 | 查看咨询师的信、预约咨询、进入系统设置 | 三项常驻操作栏 |

第一阶段只完整实现核心与主要入口。氛围入口可以先做悬停或极短反馈，避免大厅变成点击任务清单。

## 6. 前台人物规则

任心是等待室中的固定接待者，而不是咨询师。第一版人物确定为年轻男性工作室助理“任心”。他约 22–24 岁，刚大学毕业，主要负责接待、介绍、预约和引导，不提供诊断或咨询建议。

- 视觉方向：参考旧大厅实验的男用户 A，使用与等待室协调的精致二次元像素风；
- 第一版外观：深色短发、奶油色衬衫、灰绿色针织背心和简洁工作牌；
- 场景态：任心使用独立的二次元像素风站立素材，按柜台透视缩小并裁掉腰部以下，明确站在柜台后，可有轻微呼吸；
- 对话态：任心使用另一张较细腻的大半身立绘，从左下方进入并叠在全宽底部对白框后；对白框使用暖黄纸纹与胡桃木框，只承载一小句和右下角双箭头；
- 退出对白：前景立绘淡出，场景态人物继续留在柜台后；
- 不把人物烘焙进背景图，以便后续替换动作和状态；
- 场景人物与对白人物不能复用同一素材；后续多表情与动作只扩展各自状态，不改变这一分层边界。

## 7. 户外花园场景

等待室左侧窗景是一个可进入的场景入口。点击后切换到与当前窗外一致的湖畔花园全画幅画面。

- 晴天和雨天使用同一视角、同一构图和相同地标；
- 晴天表现柔和日光、云影和微风；
- 雨天表现雨丝、湿润空气和安静光线；
- 使用低成本前景层、遮罩或 CSS 实现树叶轻摆、云影与雨丝；
- 等待室原有窗帘不做动画；
- Demo 提供轻量天气预览切换，最终天气规则后续确定；
- 音乐、正念呼吸等未来功能只保留占位语义，不在第一阶段实现。

## 8. 首次咨询前说明

说明不应在用户一进入大厅时就变成长表单，但首次正式开始咨询前需要清楚呈现：

- Ling 提供情绪支持、自我探索、学习和研究辅助；
- Ling 不能替代专业心理咨询、精神科诊疗、医学诊断或危机干预；
- 用户可以随时停止、退出或删除本地会谈；
- 如存在即时自伤、伤人或其他紧急风险，应优先联系当地紧急服务和可信赖的现实支持者；
- 本地数据和隐私边界应与项目真实能力一致，不承诺尚未实现的功能。

第一阶段只验证说明如何自然进入流程，不在等待室前端任务中修改真实数据或安全契约。

## 9. 动态与分层策略

基准图是一张完整概念图。第一阶段不先重做整套分层美术，而使用低成本叠加方式验证体验：

- 独立前台人物层；
- 可交互区域使用独立触发范围，悬停或键盘聚焦时只显示缓慢呼吸的柔光圆点与小木牌，不显示星形图标或覆盖物件的大矩形高亮；
- CSS 或遮罩实现的局部提亮、树影轻摆、微尘和灯光呼吸；
- 对白、介绍和资料覆盖层；
- 场景淡入、聚焦和退出过渡。

窗帘、窗外云层等需要重新绘制或切层的动态，在原型体验确认后再决定是否制作正式资产。

## 10. 第一阶段交互原型范围

第一阶段必须完成：

- 基准图稳定展示及桌面端响应式适配；
- 等待室使用“视口层 + 等比场景画布”：16:9、16:10 与宽屏优先等比 cover，16:10 允许轻微左右裁切并向右侧功能区校正视觉中心；只有 3:2、4:3 等明显偏高且裁切会损伤主体与交互区的窗口，才完整保留主场景并用同图柔化延展层补满视口；背景、任心和热点始终共享同一坐标系，不允许分别拉伸或漂移；
- 首次进入与再次进入两种状态；
- 前台欢迎对白及“随便看看”退出路径；
- 可发现且不破坏画面的交互热点；
- 咨询师介绍、书架、右下资料桌、合照的代表性覆盖层；
- 点击窗景进入户外晴雨场景并可返回；
- 从任心或咨询师介绍中选择咨询师，沿用现有预约/新会谈逻辑进入真实咨询页；
- 咨询师介绍使用暖色无框立绘、清晰的介绍层级和专业咨询语汇；预约按钮统一为“预约咨询”，已预约状态统一为“咨询工作中”；
- 正式咨询页右上角提供“返回等待室”，形成可逆的场景切换；
- 右下角齿轮进入现有系统设置；
- 返回等待室后状态正确恢复；
- 键盘焦点、减少动态偏好和基础可访问性；
- 自动化测试与浏览器截图验证。

第一阶段不做：

- 用户角色、自由移动、寻路和碰撞；
- 大厅 NPC 自由走动；
- 正式咨询选择场景的完整美术；
- 所有书籍、留言和故事的真实内容库；
- 复杂环境动画和音效系统；
- 新的数据库、IPC 或云端能力。

## 11. 已确认与待确认

已确认：

- 使用固定视角静态场景；
- 用户没有场景角色；
- 等待室不展示咨询室房门；
- 前台是开始咨询的统一入口；
- 前台人物为年轻男性咨询师助理任心，选项位于独立的中央选择层；
- 首次欢迎状态暂用本机轻量存储，不新增数据库字段；
- 右墙照片、书架、右下资料桌和合照可以交互；右墙留言板仅作装饰，其功能合并到资料桌；
- 窗景进入同构图的晴天/雨天户外场景；
- 右下角齿轮是独立系统设置入口；
- 场景动态保持轻微、低频、不干扰；
- 当前基准图作为后续原型视觉依据。
- 对白、咨询师介绍和资料覆盖层统一使用暖黄纸纹、胡桃木框与少量灰绿色焦点提示；
- 场景像素任心与对话大立绘是同一个人物的两套独立素材；
- 八处热点只在交互时出现柔光圆点与小木牌。

原型完成后再统一审阅：

- AI 边界与安全说明的长度和呈现位置；
- 热点提示的长期使用节奏与是否需要提供全局“显示可交互区域”辅助开关；
- 五类覆盖层后续接入真实内容后的信息密度；
- 环境动态强度及是否需要声音。
- 首次正式开始咨询前的正式知情说明与确认动作。
