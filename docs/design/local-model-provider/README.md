# 本机大模型接入方案

状态：首版已实现。

## 目标

让用户在首次进入 Ling 和后续系统设置中，都能清楚选择“API 服务”或“本机模型”，并用尽量少的步骤完成连接。

本期的“本机模型”指：连接用户已经在本机启动的 OpenAI-compatible 模型服务。Ling 不在本期内负责下载模型、管理显存、启动或停止推理进程。

## 设计原则

- 保留现有「模型接入」一级菜单，不新增「本机模型」侧栏项；API 服务与本机模型是同一能力的两种连接方式。
- 首次引导先帮助用户作出易懂的选择，再展示对应字段，不在同一页堆叠所有高级配置。
- 本机模式不要求 API Key。
- 优先自动读取模型列表；自定义地址和更完整的模型配置放在系统设置中处理。
- 只把 `127.0.0.1`、`localhost` 和 `::1` 明确标记为“仅在本机”；局域网地址应提示数据会离开当前设备。
- 沿用现有暖纸、植物绿、胡桃木和酒红强调色，不引入开发者工具式黑色终端视觉。

## 信息架构

系统设置继续使用现有菜单：

> 模型接入 / 语音输入 / 个人资料 / 咨询连续性 / 咨询师扩展 / 数据与隐私 / 界面与阅读

「模型接入」页内部调整为：

1. 顶部连接方式切换：`API 服务`、`本机模型`；
2. 当前连接卡：服务类型、地址、模型、连接状态；
3. 连接配置；
4. 模型分工：会谈、会谈整理与连续性、咨询师来信；
5. 数据去向说明。

默认规则：

- 新安装且没有模型配置：将更易接入的“API 服务”放在第一位，不预选并替用户作决定；
- 已有用户：保持现有在线配置，不自动迁移或改写；
- 切换连接方式时分别保留草稿配置，保存后只有一套配置成为当前活动连接。

## 首次引导

现有第三步“连接 DeepSeek”改为“连接模型服务”，仍保留 `03 / 03` 和门廊暖纸布局。

### 第一步：选择连接方式

标题：

> 选择模型放在哪里运行

两个并列选择卡：

- **使用 API 服务**
  选择 DeepSeek（推荐）、Kimi、GLM、千问或其他兼容服务，再填写对应 API Key。
- **在这台设备上运行**
  会谈内容发送到这台设备上的模型服务；需要先安装并启动 Ollama、LM Studio 或其他兼容服务。

底部保留 `暂时跳过，进入工作室`，避免模型配置阻塞浏览。

### 本机模型的最短路径

选择“在这台设备上运行”后，在同一纸张区域内渐进展开：

1. 服务选择：`Ollama`、`LM Studio`；
2. 自动带入地址：
   - Ollama：`http://127.0.0.1:11434/v1`
   - LM Studio：`http://127.0.0.1:1234/v1`
3. 点击主按钮 `检测本机模型`；
4. 检测成功后展示模型下拉框并默认选中第一项；
5. 点击 `使用这个模型`，保存、测试并完成引导。

失败状态不只显示“连接失败”，而是按原因给出下一步：

- 服务未启动：`没有找到本机模型服务，请先启动 Ollama / LM Studio。`
- 服务可访问但无模型：`服务已连接，但还没有可用模型。请先在该工具中下载或加载模型。`
- 接口不兼容：`服务已响应，但不支持 Ling 需要的 OpenAI-compatible 接口。`
- 超时：`模型可能仍在加载，可以稍后重试。`

自定义 Base URL 与其他兼容服务放在系统设置中配置，让首次进入页面保持简洁。

### API 服务的最短路径

沿用现有 API Key 体验，但不把入口绑定到单一服务商：

1. 提供 DeepSeek（推荐）、Kimi、GLM、千问和其他兼容服务；
2. API Key 为主输入；
3. `其他 OpenAI 兼容服务` 展开 Base URL 和模型名；
4. 保存并测试成功后完成引导。

## 设置页

### 连接方式切换

页面标题仍为「模型接入」。标题下增加两段式选择控件：

> API 服务 ｜ 本机模型

使用现有植物绿表示选中，纸色底和细描边保持安静。切换只改变右侧表单，不改变侧栏位置。

### 本机模型配置卡

- 服务：Ollama / LM Studio / 其他兼容服务；
- 服务地址：预设时只读展示，可选择“自定义地址”；
- 可用模型：通过 `/models` 自动读取；
- 状态：未检测 / 服务未启动 / 已连接无模型 / 可以使用 / 连接失败；
- 操作：`检测服务`、`读取模型`、`保存并使用`。

状态卡文案强调：

> 当前地址仅指向这台设备，会谈内容不会因为模型调用离开本机。

若用户输入局域网 IP 或其他主机名，立即改为：

> 这个地址不在当前设备上。会谈内容将发送到该网络地址，请确认它由你信任的人或设备管理。

### API 服务配置卡

保留现有字段和安全存储逻辑。服务商识别、模型读取和模型分工继续复用现有能力。

### 模型能力提醒

连接成功不等于适合心理咨询。模型选择后显示一条非阻塞提示：

> 本机模型的回应质量、上下文长度和速度取决于模型与设备。建议先完成一次简短测试，再用于连续会谈。

不在首版建立硬编码“推荐模型榜单”，避免造成专业质量背书和快速过时。

## 技术方案

### 数据结构

将当前单一 `ApiSettings` 扩展为显式连接配置：

```ts
type ModelConnectionKind = "local" | "remote";
type LocalModelRuntime = "ollama" | "lm-studio" | "custom";
interface ModelConnectionSettings {
  kind: ModelConnectionKind;
  runtime?: LocalModelRuntime;
  apiBaseUrl: string;
  apiKey?: string;
  apiKeySaved?: boolean;
  apiKeyPreview?: string;
  modelName: string;
}
```

数据库继续保存非敏感设置；API Key 仍走 Electron 主进程的系统安全存储，不进入 SQLite 或备份。

### 请求层

- 继续复用 `OpenAICompatibleProvider` 的 `/chat/completions` 和 SSE 流式处理；
- 本机模式且没有访问凭据时不发送 `Authorization` 请求头；
- 模型发现继续使用 `{baseUrl}/models`；
- 连接测试区分网络不可达、HTTP 错误、无模型、响应格式错误和推理超时；
- 本机预设一律使用 `127.0.0.1`，避免 `localhost` 在不同系统中的 IPv4/IPv6 解析差异；
- 自定义 `http` 地址只在 local/LAN 模式允许，在线服务默认要求 `https`；
- 日志不得记录访问令牌、提示词、用户消息或模型回复正文。

### 兼容性

首版正式支持并在界面中提供预设：

- Ollama OpenAI-compatible API；
- LM Studio OpenAI-compatible API；
- llama.cpp server 与其他 OpenAI-compatible 服务通过“其他兼容服务”接入。

已有配置会根据 Base URL 识别为 DeepSeek、Kimi、GLM、千问或其他兼容服务，并迁移为 `kind: "remote"`；原有会谈仍保留创建时的模型名。

## 范围边界

首版包含：

- 首次引导中的本机/API 服务选择；
- 设置页中的本机模型连接；
- 无密钥请求、模型发现与连接测试；
- 中英文文案、键盘操作、窄窗口与减少动态适配；
- 旧设置迁移和自动化测试。

首版不包含：

- 在 Ling 内下载、删除、加载或更新模型；
- 自动安装 Ollama、LM Studio 或 llama.cpp；
- 显存/内存评估、模型量化与运行参数调优；
- 同时保存并动态路由多套活动模型服务；
- 将本机服务开放到局域网或公网。

## 验收标准

- 新用户可在首次引导中选择 Ollama 或 LM Studio，检测服务、读取模型并完成连接；
- 无 API Key 的本机服务可正常完成流式会谈和会谈后整理；
- 本机服务未启动、未加载模型或接口不兼容时，界面给出可执行的恢复提示；
- 用户可在设置中切换本机/在线连接，未保存改动仍受现有离开确认保护；
- `127.0.0.1` 与局域网地址的数据去向文案准确区分；
- 已有用户升级后原在线配置与历史会谈不受影响；
- API Key 或本机令牌不进入 Renderer 读回、SQLite、备份和日志。

## 推荐实施顺序

1. 扩展共享类型、凭据策略、迁移和 Provider 请求头；
2. 完成连接测试与模型发现的错误分类；
3. 重构设置页「模型接入」；
4. 重构首次引导第三步；
5. 补齐首次咨询前补连模型流程与文案；
6. 进行 Electron 原生环境的 Ollama、LM Studio 和在线 DeepSeek 回归。
