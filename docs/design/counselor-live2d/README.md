# 咨询师动态立绘方案

更新时间：2026-07-13
执行工具：Codex
状态：方案待确认

## 结论

最终目标不是制作大量独立整图，而是为每位咨询师建立一份身份锁定的分层母稿，再制作可组合的眨眼、口型、呼吸、轻微头身运动和手部动作。正式方向推荐 **Live2D Cubism + Cubism SDK for Web**；先用程灵做一位咨询师的垂直原型，通过后再复制参数规范到周舟和林乐水。

现有“90 张整图候选”暂停。它会反复重绘脸、发型、衣物、杯子和椅子，也无法保证动作切换时无跳变。新方案只需要先确认每位咨询师的一张主母图，以及少量真正改变轮廓的手臂/手势替换件。

## 技术路线比较

| 路线 | 适配现有立绘 | 眨眼/口型 | 动作混合 | Electron 接入 | 许可与成本 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| Live2D Cubism | 很高，面向分层位图人物 | 原生参数体系 | 支持淡入淡出、表情和分部动作 | Web SDK 可在 renderer 的 WebGL Canvas 运行 | Editor 与 SDK 有专有许可，发布前必须核对 | **推荐正式方案** |
| Spine | 高，适合骨骼/网格动画 | 可做，但面部参数化不如 Live2D 直接 | 动画混合成熟 | 有 Web Runtime | 编辑器和 Runtime 使用受商业许可约束 | 适合偏游戏骨骼动作，不作为首选 |
| Rive | 中低，更适合矢量和动效组件 | 可做 | 状态机成熟 | React/Web Runtime 很方便 | Runtime 导出取决于订阅方案 | 不适合保留当前细腻位图人物质感 |
| PixiJS 分层 PNG | 中，所有规则需自建 | 可用帧替换实现 | 需要自行实现状态机、插值和遮挡 | 最容易接入现有 React/Electron | MIT 生态，分发简单 | 可做低成本原型或 Live2D 许可后备 |
| Inochi2D | 理念匹配且开源 | 可做 | 支持参数形变 | 官方主要提供 D/C FFI、Unity/Godot，缺少成熟 Web 路径 | BSD-2-Clause | 暂不承担首版 Electron 集成风险 |

## 为什么推荐 Live2D

1. 现有素材是细腻位图插画，不是矢量图；Live2D 的 PSD 分层和 ArtMesh 直接针对这一类人物。
2. 官方标准参数已经覆盖双眼开合、嘴型、嘴巴开合、头部角度、身体角度、手部与头发物理。
3. 眨眼和口型可以作为独立参数叠加在身体动作之上，不需要为每个组合再生成整张图片。
4. Web SDK 支持 TypeScript；官方也提供将左右手动作交给不同 Motion Manager 的方案，适合“说话时嘴动，同时偶尔做手势”。
5. 动作和表情可配置淡入淡出，能得到文字游戏人物立绘的柔和切换，而不是当前 PNG 整体交叉淡化的重影。

## 每位咨询师的美术生产规格

### 母图

- 工作画布：`2048 × 3072`，运行时逻辑画布：`1024 × 1536`。
- 正脸和视线朝向用户；椅子、骨盆、交叉腿和身体重心轻微朝画面左侧。
- 人物、椅子、杯子在三位咨询师之间使用统一眼睛锚点、坐面锚点、椅脚锚点与杯子安全区。
- 一位咨询师只批准一张身份母图。脸、发型、衣服、首饰、椅子和杯子此后不再通过整图生成改变。

### PSD 最低拆件

- 后层：椅背、后发、身体后侧衣物。
- 头脸：脸底、左右眉、左右眼白、左右虹膜、上下眼睑/睫毛、鼻、耳、腮红。
- 嘴部：嘴部底色、牙齿/口腔、上唇、下唇；预留闭合、半开、张开形变。
- 头发：后发、左右侧发、前发、少量可动发束；不保留大量碎发。
- 身体：颈、躯干、披肩/开衫、裙/裤、左右腿、鞋。
- 手臂：左右上臂、前臂、手、袖口；杯子和持杯手独立。
- 椅子前层：左右扶手、坐垫前缘、椅腿，用于正确遮挡手臂和衣物。
- 补画层：眼皮下方、嘴周、颈肩、肘部和杯子后方必须补齐被原画遮住的像素。

## 动画参数

三位咨询师使用同一套参数 ID，便于共享运行时代码和基础动作：

| 参数 | 用途 | 建议幅度 |
| --- | --- | --- |
| `ParamEyeLOpen` / `ParamEyeROpen` | 独立眨眼 | `0–1` |
| `ParamEyeBallX` / `ParamEyeBallY` | 极轻微视线变化 | 不偏离用户方向 |
| `ParamMouthOpenY` | 说话口型开合 | `0–0.75`，避免夸张 |
| `ParamMouthForm` | 微笑/中性嘴型 | 小幅变化 |
| `ParamAngleX/Y/Z` | 头部轻动 | 约 `±3–5°` |
| `ParamBodyAngleX/Z` | 身体前倾/回正 | 约 `±2–4°` |
| `ParamBreath` | 呼吸 | 低频、低幅 |
| `ParamHandL` / `ParamHandR` | 手势与持杯状态 | 离散姿态间平滑插值 |
| `ParamHairFront/Side/Back` | 发丝惯性 | 只动主要发束 |

## 三个功能动作

1. `present`：安静在场。自动眨眼、呼吸、极轻微头身漂移，双手或单手稳定持杯。
2. `listening`：保持正脸看用户，身体向左前倾，嘴巴停止；目光更聚焦，手势收敛。
3. `responding`：保持正脸看用户，嘴型随文本节奏运动；手部动作作为独立短动作偶发播放，然后自然回到持杯姿态。

`thinking` 不单独制作完整姿态：复用 `listening` 的身体姿态，降低嘴部与手部活动，增加一次轻微停顿即可。错误态也不另画，只降低饱和度并停止主动动作。

## 运行时状态映射

| Ling 状态 | 身体动作 | 眼睛 | 嘴巴 | 手部 |
| --- | --- | --- | --- | --- |
| `idle` | `present` 循环 | 2.8–6.5 秒随机眨眼 | 闭合 | 偶发极小调整 |
| `listening` | 600–850ms 淡入前倾 | 正常眨眼 | 闭合 | 收回/扶杯 |
| `connecting/thinking` | 保持倾听或轻回正 | 偶发慢眨眼 | 闭合 | 静止 |
| `streaming` | 500–700ms 淡入回应 | 正常眨眼 | 文本节奏驱动 | 6–12 秒随机一次短手势 |
| `error` | 回到在场 | 正常或慢眨眼 | 闭合 | 静止 |

首版没有语音，因此嘴型不按音素，而按流式文本生成“说话包络”：收到新字符时张嘴，逗号/句号处停顿，连续输出时在 `0.15–0.65` 之间平滑变化。未来接入 TTS 后再改为音量或音素驱动。为了避免机械感，口型、眨眼和手势使用彼此独立的时钟。

## 前端接入边界

- 新增 `CounselorLive2DStage`，只替换当前右侧人物渲染层；消息区、输入区和状态卡保持不变。
- renderer 内加载模型和动作，首版不改 Electron main、preload、IPC 或数据库。
- 预加载当前咨询师的模型、纹理和三个基础动作；切换咨询师时释放旧模型，避免 WebGL 与纹理内存累积。
- 保留现有透明 PNG 作为加载失败、禁用 WebGL 和 `prefers-reduced-motion` 的回退图。
- 动画控制器只接收语义状态：`present/listening/thinking/responding/error-soft`，不让页面直接操作模型参数。

## 推荐实施顺序

### 阶段 A：程灵垂直原型

1. 重新确认一张符合当前右栏布局的程灵母图。
2. 完成最低 PSD 拆件，只做眨眼、口型、呼吸、身体前倾和一组回应手势。
3. 在独立 Demo 中验证动作混合、遮挡和 60 FPS。
4. 接入当前右栏，验证流式文本口型、状态切换、快速切会谈和 reduced-motion 回退。

### 阶段 B：模板化

1. 冻结三位咨询师共享参数 ID、动作名、锚点和模型目录结构。
2. 把程灵动作模板复制到周舟和林乐水，再分别调整头发、衣物和杯椅物理。
3. 为三人分别制作一组个性化回应手势，避免完全同模。

### 阶段 C：生产验收

1. 检查眼睑、嘴角、手指、杯把、袖口、披肩穗子和椅子前后遮挡。
2. 在实际右栏尺寸与三套咨询室背景上验收，不只看 Cubism Editor 大图。
3. 连续运行 30 分钟，检查帧率、内存、WebGL context 丢失和切换残影。
4. 完成许可证复核后再决定 SDK Core、模型文件和构建脚本如何进入开源仓库与发布包。

## 许可闸门

Live2D 允许免费开始开发验证，但正式发布涉及 SDK Release License；个人和部分小规模主体可能豁免，具体仍需按产品形态确认。官方 Web Samples 仓库也没有直接包含 Cubism Core，而是要求单独下载。Ling 是开源桌面应用，因此在正式接入前必须明确：

1. 是否允许把 Cubism Core 放入公开仓库或发布包；
2. Ling 是否落入需要单独协议的应用类型；
3. 三位咨询师模型文件是否允许随开源仓库分发；
4. 若许可不可接受，是否切换到 PixiJS 分层 PNG 后备方案。

## 本阶段验收标准

- 用户确认正式方向为 Live2D，或选择 PixiJS 后备路线。
- 用户确认先做程灵单人垂直原型，而不是同时制作三人完整模型。
- 程灵母图与首版动作范围确认后，再进入独立美术制作与前端集成分支。
