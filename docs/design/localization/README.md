# Ling 多语言与英文版本

## 当前状态

`feat/english-localization` 已完成首期工程实现：

- 首次欢迎页和系统设置都可选择“简体中文 / English”，选择会写入本机设置并立即生效；
- UI 短文案使用类型安全目录，人物资料、知情同意、用户指南、危机说明和故事使用按语言选择的专业内容；
- 三位咨询师、共享咨询价值观、实时安全政策、李燕云督导以及所有会谈后任务均有独立英文提示词；
- 新会谈生成 V3 提示词快照并冻结 `locale`，标题、摘要、概念化、督导、备忘录、来信、导入资料和 Markdown 导出沿用会谈语言；
- 最新主线新增的本地/云端语音输入、快捷键、麦克风权限说明、花园呼吸练习和自然声音已同步支持中英文；
- 不按每条消息自动路由提示词；用户可自然使用中英文，明确提出切换语言时模型持续跟随，整套专业提示词和后台产物仍以新建会谈时的语言为准；
- 生产品牌素材已复核：舟形标识本身不含烘焙文字，`Ling` 字标无需翻译，工作室名称和图片替代文本由 HTML/语言目录切换；
- `npm run localization:verify` 会检查目录键、提示词镜像、英文内容中的中文残留、未登记 Renderer 中文和源文指纹。

英文专业内容目前属于工程就绪版本；正式面向英语地区发布前，仍需双语心理专业人员、法律/合规人员和目标地区安全资源负责人审阅。

语言路由的真实模型矩阵、淘汰方案与评测数据属于内部研究记录，不进入公开仓库。公开仓库只保留当前生效的本地化规则和回归测试。

## 目标

在系统设置中提供“语言”选项，首期支持简体中文和英文，并让以下内容随语言一致切换：

- App 界面、无障碍标签、错误和状态提示；
- 三位咨询师的姓名展示、专业取向、人物介绍与场景对白；
- 知情同意书、用户指南、危机支持说明和故事内容；
- 咨询师实时回复、标题、摘要、概念化、督导、备忘录和来信；
- Markdown 导出的产品标题与结构标签。

方案需要允许未来继续增加语言，并能在中文原文调整后发现英文未同步的问题。首期不自动翻译用户已经写下的消息、既有会谈内容或已经生成的来信。

## 核心判断

### 1. 这不是一个简单的界面翻译开关

Ling 的语言至少包含三个层次：

1. **界面语言**：按钮、表单、状态、错误、日期和无障碍文本；
2. **专业内容语言**：人物资料、知情同意书、用户指南、危机说明和故事；
3. **模型工作语言**：咨询师核心提示词、会谈场景、安全政策、督导和会谈后任务。

三层应共用同一个用户语言设置，但在代码和内容仓库中分别管理。不能把所有中文替换为零散的 `t("...")` 后就认为功能完成。

### 2. 咨询师提示词需要正式英文版

需要。仅在中文提示词末尾追加“请用英文回答”可以作为旧会谈切换语言时的兼容手段，不适合作为英文版本的正式实现，原因包括：

- 心理动力、人本、焦点解决、中国传统心性等专业概念需要稳定的英文术语；
- 中文句式中的分寸、关系位置和禁忌表达不一定能由模型自行等价转换；
- 安全边界、非诊断表述和危机回应不能依赖临场翻译；
- 全中文长提示词会增加英文对话中的语言漂移和不自然表达。

正式英文版应覆盖三位咨询师核心提示词、三套会谈场景、实时安全政策、李燕云督导提示词以及概念化、来信、备忘录等全部任务提示词。

### 3. 语言与服务地区必须分开

英文用户不等于美国用户，中文用户也不一定在中国大陆。`locale` 只决定语言和格式，不能据此选择危机号码、法律说明或可用服务。

在没有单独的 `serviceRegion` 和经过核验的地区资源表之前，英文版必须明确当前危机资源和适用范围，不能因界面变成英文就暗示 Ling 已具备国际危机支持能力。面向海外公开发布前，应另开地区化功能。

## 数据与运行时设计

### 语言类型

首期只允许两个稳定值：

```ts
export type SupportedLocale = "zh-CN" | "en-US";
```

在 `UserSettings` 中新增 `locale`。兼容规则：

- 旧设置没有 `locale` 时固定迁移为 `zh-CN`，避免现有用户升级后突然变成英文；
- 新安装可读取操作系统支持的语言作为建议值；
- 首次欢迎页在进入知情说明和模型配置前提供清晰的语言选择，让英文用户不必先穿过中文界面；
- 设置页保存后立即切换所有静态界面和专业内容，不要求重启。

### 会谈和生成内容

在会谈及生成材料中记录 `locale`，用来确定模型输出、导出标题和后续后台任务的语言，也为排查混合语言问题保留依据。

推荐把提示词快照升级为新版本并记录：

```ts
interface CounselingPromptSnapshotV3 {
  version: 3;
  locale: SupportedLocale;
  // 保留现有冻结字段
}
```

行为规则：

- 新会谈使用创建时所选语言的完整提示词套件，并冻结进快照；
- 切换设置后，App 静态内容立即切换；
- 已存在的消息、摘要和来信保留原文，不做静默机器翻译；
- 进行中的会谈继续沿用创建时冻结的语言。切换设置只影响静态界面和之后新建的会谈，避免同一会谈的专业框架、安全政策与后台材料发生语言漂移；
- 旧快照没有 `locale` 时按 `zh-CN` 处理；
- 历史会谈继续时明确沿用该会谈记录的语言，用户主动改变语言后再更新会谈语言，不从消息文本猜测。

实时安全政策目前每轮动态注入。它必须按会谈语言选择对应版本，不能按设置页当前语言选择，否则查看或继续旧会谈时可能注入错误语言。

## 内容组织

### 界面短文案

建立类型安全的语言目录，中文是语义源：

```text
apps/desktop/src/renderer/localization/
├── index.ts
├── useLingua.ts
└── catalogs/
    ├── zh-CN.ts
    └── en-US.ts
```

要求：

- 使用稳定语义键，例如 `settings.language.title`，不使用整句中文作为键；
- 英文目录必须满足中文目录的完整类型，缺键时构建失败；
- 参数、复数、日期、时间和数字统一使用 `Intl`，不在组件中拼接语序；
- 图片上的中文文字需要列入素材审计，优先改为“无字底图 + HTML 文本层”；
- 开发工具、测试夹具和仅供维护者阅读的中文可以不纳入产品语言目录。

### 长篇和专业内容

知情同意书、危机支持、用户指南、人物介绍和故事不应塞进短文案字典。按内容 ID 和语言分别保存：

```text
content/
├── zh-CN/
│   ├── informed-consent.md
│   ├── crisis-support.md
│   └── ...
├── en-US/
│   ├── informed-consent.md
│   ├── crisis-support.md
│   └── ...
└── manifest.ts
```

解析器只识别与语言无关的稳定结构，不应继续依赖“目录”“版本信息”等中文标题定位章节。知情同意书的两处入口继续读取同一份当前语言正文。

知情同意采用统一的语义内容版本。纯翻译修正可记录翻译修订号；事实、风险、数据处理或用户权利发生变化时，所有语言共同提升内容版本并触发重新确认。确认记录增加用户阅读时的语言，但同一语义版本切换语言不重复要求确认。

### 模型提示词

正式运行提示词按语言镜像：

```text
packages/core/src/prompts/
├── zh-CN/
│   ├── counselor-cores/
│   ├── shared/
│   ├── supervisor-cores/
│   ├── tasks/
│   └── policies/
├── en-US/
│   └── ...
└── promptManifest.ts
```

注册表函数显式接收 `locale`，禁止在 Core 层直接读取 Renderer store。所有调用链都必须把会谈或任务的语言传入：

```ts
getCounselorCorePrompt(counselorId, locale);
getTaskPrompt(task, locale);
getPolicyPrompt(policy, locale);
```

提示词中的输出格式字段尽量使用稳定、与语言无关的 JSON key；展示给用户的 Markdown 标题再按语言生成。这样可避免数据库和解析逻辑因英文标题变化而失效。

## 防止中英文漂移

仅靠人工记得“顺便改英文”不可靠。需要同时使用以下约束：

1. **键和文件完整性检查**：每种语言必须包含相同的 UI key、内容 ID 和正式提示词 ID；
2. **源文指纹**：英文翻译元数据记录它对应的中文源文 SHA-256。中文源文变化而英文仍指向旧指纹时，CI 失败；
3. **显式确认命令**：翻译者完成英文更新后运行校验命令刷新指纹，不能由普通构建自动刷新；
4. **版本差异清单**：校验输出具体到文案 key 或文件，便于每次 PR 审阅；
5. **术语表和英文风格指南**：统一 client、counselor、informed consent、case conceptualization、holding environment 等术语，并记录三位咨询师姓名的官方罗马字和工作室官方英文名；
6. **所有新增中文产品文案必须进入目录**：增加静态扫描，阻止 Renderer 和正式提示词目录出现未登记的中文字符串；允许名单只覆盖日志、测试数据和开发注释。

源文指纹用于提醒同步，不代表翻译已经专业准确。英文内容仍需人工审阅。

### 修改文案时的维护流程

1. 短界面文案同时修改 `catalogs/zh-CN.ts` 和 `catalogs/en-US.ts`；TypeScript 和校验脚本会阻止缺键。
2. 人物资料、长文、故事或提示词先修改中文语义源，再同步对应英文文件。
3. 运行 `npm run localization:verify`。若出现 `source changed`，逐项审阅并更新英文，不要直接刷新指纹。
4. 完成英文同步与专业复核后，运行 `npm run localization:update-hashes` 确认新的对应关系。
5. 提交前至少运行 `npm run typecheck`、`npm test -- --run` 和 `npm run build`。

`source-manifest.json` 是需要人工确认的翻译对应表。刷新哈希只表示“已核对这次源文变更”，不表示自动翻译或专业审阅已经发生。

## 专业质量与安全验收

英文不是逐句直译，建议采用“专业翻译 + 心理咨询审阅 + 产品一致性复核”：

- 咨询师人物介绍与提示词由熟悉相应取向的双语心理专业人员审阅；
- 知情同意、隐私和适用范围由熟悉目标发布地区的法律/合规人员复核；
- 建立英文固定评测集，覆盖情绪支持、关系冲突、现实决策、悲伤、异常体验、自伤和伤人风险；
- 分别检查三位咨询师的角色区分、自然度、非诊断边界、不虚构人类感受、不过度承诺和危机优先级；
- 英文安全评测不能只翻译现有中文测试题，需要加入英文用户真实表达方式、缩写和委婉风险表达；
- 对模型真实运行结果进行盲评，不能仅以 TypeScript 测试通过作为专业语言验收。

## 分阶段实施

### 第一阶段：基础设施与设置

- 增加 `SupportedLocale`、设置持久化、旧数据兼容和首次欢迎页语言选择；
- 建立类型安全 UI 目录、`Intl` 格式化和语言切换入口；
- 先覆盖启动、设置、等待室框架、错误提示和无障碍标签；
- 加入目录完整性、源文指纹和未登记中文扫描。

验收：切换语言无需重启；重启后保留；旧用户仍为中文；英文用户能从首次启动完成基础设置。

### 第二阶段：全部静态内容

- 迁移三位咨询师资料、任心对白、咨询流程对白、状态短句和故事；
- 建立英文知情同意、危机支持和用户指南；
- 处理带中文的图片与品牌文字；
- 本地化导出结构和日期格式。

验收：英文模式中不再出现无意的中文产品文案；两处知情同意入口内容一致。

### 第三阶段：模型与会谈生命周期

- 完成全部正式英文提示词；
- 提示词快照升级并记录语言；
- 实时会谈、标题、摘要、概念化、督导、备忘录和来信按会谈语言生成；
- 定义进行中会谈切换、旧会谈继续和后台任务重试行为。

验收：新英文会谈从系统提示词到所有后台材料均为英文；旧中文会谈不被意外改写；安全政策语言始终与会谈一致。

### 第四阶段：专业评测与发布准备

- 完成术语、心理专业、知情同意和英文安全评测；
- 对三位咨询师做真实模型多轮盲评；
- 明确首个英文发布地区；若面向中国大陆以外地区，先完成地区化危机资源和法律文本。

验收：通过产品、专业、安全和目标地区发布审查后，才把英文标记为正式支持；此前可标记为 Beta。

## 首期不做

- 自动翻译用户历史消息和已经生成的专业材料；
- 根据消息内容自动猜测语言；
- 把语言设置同时当作国家、法律适用地或危机资源地区；
- 在缺少人工审阅时宣称英文心理咨询内容与中文版本具有完全相同的专业效力；
- 为未来所有语言预先搭建翻译平台或远程内容服务。

## 最终验收清单

- 设置中可选择“简体中文 / English”，切换即时生效并本地保存；
- 首次启动在阅读任何重要说明前即可选择语言；
- 界面、人物介绍、知情同意、指南、危机说明和无障碍文本完整切换；
- 三位咨询师和所有会谈后任务拥有独立、已审阅的英文提示词；
- 会谈及提示词快照记录语言，旧数据向后兼容；
- 中文源文变化而英文未同步时，CI 明确失败；
- 英文模式不存在未登记中文，中文模式不存在无意英文占位；
- 历史用户内容不被静默翻译或覆盖；
- 危机资源选择不由语言设置推断；
- 英文真实模型安全与专业质量评测通过后再正式发布。
