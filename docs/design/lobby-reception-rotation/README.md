# 三位咨询师前台轮值与“随便聊聊”

状态：第二版已接入本地预览，待文案审核

## 设计结论

前台由程灵、周舟、林乐水三位 AI 咨询师轮流值班，不再使用独立的任心接待身份。

- 用户第一次进入工作室时固定由程灵迎接。
- 首次进入当天关闭并重开，仍由程灵值班。
- 之后按本地自然日稳定轮换：程灵 → 周舟 → 林乐水。
- 同一天不会因为重开 App 随机换人。
- 当前值班咨询师成功进入会谈后，前台交给排班顺序的下一位；交班保持到当天结束。
- 取消预约、模型连接失败、拒绝知情同意或创建会谈失败，都不会触发交班。

这样既保留程灵作为稳定的第一印象，也让再次进入时有合理的人员变化。随机只用于“随便聊聊”主题去重后的抽取，不用于值班人选择。

## “随便聊聊”：带着日常感说清真实功能

入口文案保持为“随便聊聊”，但对白不是开放闲聊，也不调用咨询模型。当前值班咨询师会从当天的工作室小事接一句，再只用文字说明一个真实存在的功能。对白结束后不直接跳转功能，用户可以自己从等待室的热点和底栏探索：

- `再多聊聊`：抽取当前咨询师的另一项功能说明；
- `先聊到这，谢谢`：回到等待室。

内容池同时覆盖工作室日常、前台轮值、资料桌、湖畔花园、工作室相册、预约咨询、会谈记录、咨询师的信、系统设置和语音输入。咨询师介绍仍由“请带我看看工作室”负责；“随便聊聊”不再重复介绍咨询师。

会谈记录和咨询师的信只有在用户已经有结束会谈时才进入导览候选，避免对没有内容的用户做不准确的预告。

## 状态与边界

前台状态保存在本地 `ling.lobby.receptionDuty.v1`，只包含：

- 首次进入日期与当天值班人；
- 交班来源和会谈 ID；
- 最近五条已展示的“随便聊聊”内容。
- 已经在前台见过的咨询师。

它不进入模型上下文、不写入咨询记忆，也不读取用户会谈正文。日期使用设备本地时区，避免 UTC 跨日导致夜间突然换班。

实现层分为：

```text
lobbyStorage.ts
  日期、轮值、交班和已介绍主题的本地状态

smallTalkContent.ts
  三位咨询师带日常连续感的功能说明主文案

dialogueContent.ts
  首次、再次、导览、预约和交班对白

useLobbyController.ts
  状态编排、去重和对白返回
```

## 文案审查结论

已删除或避免以下风险表达：

- 不再声称咨询师写过某个故事、读过某个用户故事或拥有可验证的现实生活经历；
- 不使用“疗愈”“治愈”“让你马上平静”等治疗承诺；
- 不把花园呼吸练习描述成治疗、诊断或效果保证；
- 不把本地保存说成“绝不离开设备”，明确保留模型服务和可选云端语音的边界；
- 不暗示相册、前台或功能导览会读取用户会谈内容；
- 不把知情同意、安全支持做成玩笑或稀有彩蛋；
- 不介绍当前尚未完成的 PDF、DOCX、OCR、云同步等能力。

日常连续感只来自工作室内部的轻量细节，例如轮班、相册中的杯子和不同咨询师对同一件事的反应。这些句子服务于角色与功能表达，不替代专业说明，也不暗示咨询师拥有可验证的现实线下经历。

## 验收标准

### 轮值

- 干净设备第一次进入显示程灵；首次日重开仍显示程灵；
- 后续自然日按三人顺序变化；
- 与当前值班咨询师成功进入会谈后，下一次回到等待室显示接班人并出现一次交班对白；
- 失败或取消流程不交班；
- 切换中英文不改变值班人。
- 第一次在前台见到某位咨询师时才自我介绍；再次见面不重复名字。

### “随便聊聊”

- 前台主选项为预约、工作室导览、随便聊聊和离开；
- 每段只谈一个工作室细节或真实功能；
- 同一位咨询师最近五条内容不重复；换班后，同一功能可以用另一位咨询师的说法重新出现；
- 三位咨询师说法不同，但功能事实一致；
- 没有结束会谈时不显示记录和来信导览；
- “随便聊聊”只输出文字说明，不替用户打开功能入口；用户仍可自行点击等待室里的热点和底栏。
