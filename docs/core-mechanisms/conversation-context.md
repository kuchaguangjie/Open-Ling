# Ling 对话上下文核心机制

更新日期：2026-07-30

本文描述实时咨询模型每轮实际收到什么。会谈结束后的概念化、督导和备忘录链路见 `memory-system.md`。

## 每轮上下文结构

```text
1. 会谈创建时冻结的咨询师快照
   = 咨询师核心 + 共享咨询价值 + 会谈场景 + 可选语言风格 + 团队提示 + 模型运行契约

2. 当前咨询伦理与实时安全规则

3. 用户主动填写的基础个人资料（可选）

4. 本次会谈滚动摘要（可选）
   仅当本次会谈的较早原文因预算被省略时注入

5. 会谈创建时冻结的咨询备忘录（可选）

6. 本次会谈最近原文、附件展开内容与当前用户消息
```

以上是语义结构，不承诺所有模型都使用相同的消息位置。模型运行契约可能选择单一 system message、拆分后的多个 system message，或把共享价值和会谈场景放到最后一条用户消息前作为 reasoning prefix；咨询师核心、伦理和实时安全边界仍保持最高约束层级。风险路由命中时还会追加经过审核的危机原则强调。

当前用户消息和最近原文优先于滚动摘要、基础资料和咨询备忘录。咨询备忘录被明确标注为可修正的内部理解，不是事实档案、诊断结论或咨询计划。

## 短会谈与长会谈

短会谈：

```text
冻结快照 + 当前伦理/安全 + 基础资料 + 冻结备忘录 + 全部本次会谈原文
```

长会谈：

```text
冻结快照 + 当前伦理/安全 + 基础资料 + 本次会谈滚动摘要 + 冻结备忘录 + 最近原文窗口
```

默认预算：

```text
模型上下文窗口估计：1,000,000
本次会谈历史原文预算：80,000
滚动摘要预热阈值：40,000
滚动摘要增量更新阈值：12,000
基础个人资料预算：2,000
咨询备忘录预算：4,000
当前用户长输入提醒阈值：20,000
当前用户消息硬上限：80,000
```

当前估算器以字符数近似 token 数。历史原文超过预算时，从最新消息向前保留；只有确实省略了较早消息且已有摘要时，才注入滚动摘要。摘要不可用时保留最近原文并记录审计警告，不阻断咨询。

## 会谈级冻结

- 新会谈创建时冻结咨询师核心、共享咨询价值、咨询场景、可选语言风格、团队提示、语言、咨询师包版本、内容哈希和模型运行契约；咨询备忘录使用独立快照冻结。
- 同一会谈的每一轮都读取这两份冻结版本，不受后台提示词或记忆更新影响。
- 继续原会谈仍使用原会谈自己的冻结版本、本次原文和滚动摘要。
- 用户关闭“带入过去理解”后，新会谈冻结一个不含咨询备忘录的关闭快照。
- 咨询伦理、实时安全策略和风险强调独立注入，不属于咨询师人格或会谈冻结快照。

这保证一次咨询的关系姿态与跨会谈理解不会在中途突然改变。

## 不进入实时上下文的内容

以下资料会保存在本地并用于结束后的复盘，但不直接注入实时咨询：

- 单次完整个案概念化；
- 长期完整个案概念化；
- 李燕云完整督导意见；
- 旧会谈原始消息；
- 旧会谈候选摘录或自动检索结果。

正常对话不执行历史搜索、路由判断或额外的小模型调用。跨会谈连续性只由创建会谈时冻结的一份咨询备忘录承担。

## 基础个人资料

基础个人资料只使用用户主动填写的称呼和背景。它以独立系统消息注入，并明确说明：

- 资料由用户主动填写；
- 只用于称呼和基本背景理解；
- 不是长期记忆或对用户的定论；
- 当前表达始终优先。

头像和文件名不进入模型上下文。

## 滚动摘要

滚动摘要只承接当前会谈内部被裁剪的较早原文，偏事实和脉络，不写诊断、咨询建议、个案动力或咨询师反思。

生成和注入彼此分离：系统可以提前在后台生成，但只有本次会谈原文被裁剪时才注入。生成失败不能覆盖旧摘要，也不能推进已覆盖范围。

## 长输入与附件

- 普通输入作为用户消息进入上下文。
- 超过 20,000 字符的输入自动保存为本地资料附件，聊天消息只保留说明和引用。
- 文本资料在 200,000 字符以内可展开全文；更长时使用已保存的事实性资料摘要，并明确它不是完整原文。
- 当前用户原文完整保存在本地，不静默丢弃。
- 当前只解析文本与 Markdown；其他格式先作为附件记录。

## 上下文审计

每轮请求生成脱敏上下文计划，记录：

- 各预算值与估算量；
- 哪些本次会谈消息被纳入或省略；
- 滚动摘要、基础资料和咨询备忘录是否存在、注入或截断；
- 长输入、缺少摘要或预算超限等警告。

审计不保存消息正文、提示词正文、资料正文、摘要正文、备忘录正文或 API Key。
