# Ling 记忆系统核心机制

更新日期：2026-07-15

本文只描述当前有效机制。Ling 的记忆服务于咨询关系连续性，不是个人助理式事实库，也不追求让模型随时翻查全部历史。

## 当前记忆分层

```text
基础个人资料
当前会谈原文与滚动摘要
单次完整个案概念化
长期完整个案概念化
李燕云督导意见
咨询备忘录
```

- 基础个人资料：用户主动填写的称呼和背景，可进入实时上下文。
- 当前会谈原文：实时咨询的第一手材料；过长时只保留最近原文，并用滚动摘要承接本次会谈中被省略的较早部分。
- 单次完整个案概念化：会谈结束后，由当前咨询师基于本次会谈材料写成的完整工作记录。
- 长期完整个案概念化：同一咨询师跨会谈持续更新的纵向工作地图。
- 李燕云督导意见：独立督导师审阅会谈与概念化后给咨询师的内部意见。
- 咨询备忘录：原咨询师以本次会谈原文核对材料归属，再综合自己的概念化和督导意见写成的精简接续材料，也是唯一进入后续新会谈的跨会谈咨询记忆。

单次概念化、长期概念化和督导意见都完整保存在本地，但不直接进入实时咨询上下文。系统不再生成单次或长期 Brief。

## 实时咨询上下文

每轮模型请求按以下顺序组装：

```text
咨询师核心提示词 + 共同咨询价值观 + 咨询对话场景提示词 + 团队提示词
+ 基础个人资料（如有）
+ 本次会谈滚动摘要（仅本次会谈较早原文已被裁剪时）
+ 本会谈创建时冻结的咨询备忘录（如启用且存在）
+ 当前实时咨询安全策略
+ 本次会谈最近原文与当前用户消息
```

规则：

- 来访者当前表达始终优先于备忘录和旧理解。
- 一场会谈从创建到结束始终使用同一份咨询备忘录快照，中途不切换。
- 继续同一次会谈时，沿用原快照、本次会谈原文和滚动摘要。
- 实时对话不自动搜索旧会谈原文，不调用历史路由模型。
- 单次完整概念化、长期完整概念化和督导意见不直接注入实时咨询。
- 用户关闭“带入过去理解”时，新会谈保存关闭状态的空快照。

## 会谈结束后的复盘链路

用户结束会谈后，后台按顺序执行：

1. 当前咨询师基于本次会谈材料生成单次完整个案概念化。
2. 从第二次会谈开始生成或更新长期完整个案概念化。
3. 李燕云审阅本次会谈材料、咨询师核心取向、单次完整概念化和最新长期完整概念化，生成督导意见。
4. 原咨询师以本次会谈原文核对材料归属，再结合单次完整概念化、最新长期完整概念化和督导意见，写成咨询备忘录。
5. 每个产物只在会谈仍保持同一次结束状态时发布；旧周期失效后，迟到结果不得覆盖新周期。

长期完整个案概念化的材料固定为：

```text
首次生成：截至本次为止的全部单次完整个案概念化 + 本次会谈材料

后续更新：上一版长期完整个案概念化
        + 最近 3 次单次完整个案概念化
        + 本次会谈材料
```

本次会谈的单次完整概念化通常已经包含在“最近 3 次”中；额外提供本次会谈材料，是为了让咨询师核对原始语境。上一版长期完整概念化承接更早历史，新材料可以修正或撤回旧理解。

这里没有“较早会谈证据选择”、候选摘录或额外模型检索步骤。

## 新会谈与继续原会谈

- 新建同一咨询师的下一场会谈不等待上一场后台复盘完成；主进程只串行结束遗留 active、清理旧 draft 并创建新 draft。
- 新会谈创建时只读取当时已经 ready 的该咨询师最近一份咨询备忘录并冻结；后台后来完成的新备忘录不会热更新到已创建会谈。
- 没有 ready 备忘录或用户关闭咨询连续性时，新会谈使用空快照，不读取旧 Brief、旧会谈原文或其他咨询师材料。
- 用户在复盘期间或复盘完成后选择“继续本次咨询”，本次复盘批次及其产物失效；原会谈恢复为进行中。
- 用户再次结束该会谈时，以新的结束时间重新运行整条复盘链路。

## 滚动摘要的边界

滚动摘要只处理同一场会谈内部的长度问题：

- 它概括本次会谈中未逐字注入的较早原文。
- 只有确实裁剪了本次会谈原文时才进入上下文。
- 它不是跨会谈记忆，不是个案概念化，也不替代咨询备忘录。

## 心理咨询边界

- 概念化和督导内容都是可修正的工作理解，不是事实档案或诊断结论。
- 前后矛盾、变化或含混应保留为可继续理解的材料，不自动覆盖为“用户纠正后的事实”。
- 咨询备忘录只保留重新进入咨询关系所需的核心线索，不形成固定咨询计划，也不要求咨询师主动提及其中的人物和事件。
- 重要人物和事件在长期概念化与咨询备忘录中保留其来源和当时意义，避免写成已经核实的客观事实。
- 来访者对“可能被如何理解”的担心，与咨询师实际说过的话必须分开记录；任何关于偏离、道歉或修复的描述都以本次会谈原文为准。
