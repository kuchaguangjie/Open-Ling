## 已确认问题

### P1：自然收尾后的“查看历史记录”按钮无响应

- 复现：正常结束咨询，逐句点击“继续”直到最后一句，再点击“查看历史记录”。
- 实际：按钮可见、可点击，但页面无变化；“返回等待室”仍可用。
- 原因：最后一句仍处于 `closing` 状态，界面却提前渲染了只接受 `closing-menu` 状态的操作菜单。`OPEN_HISTORY` 在状态机中只处理 `closing-menu`，因此事件被静默忽略。
- 代码：`apps/desktop/src/renderer/pages/CounselingRoomPage.tsx`、`apps/desktop/src/renderer/flows/consultation/consultationFlowStore.ts`、`apps/desktop/src/renderer/flows/consultation/consultationFlowMachine.ts`
- 处理：已修复。`OPEN_HISTORY` 现在同时接受自然播放到最后一句的 `closing` 和跳过收尾后的 `closing-menu`；新增自然收尾回归测试，原有跳过路径不变。

### P2：自定义 OpenAI 兼容服务返回的模型会被硬编码过滤

- 复现：Base URL 指向正常返回 `/models` 的兼容服务，模型 ID 为 `audit-model` 或其他非 `deepseek-*` 名称。
- 实际：请求成功但界面显示“没有读取到可用模型”；改成 `deepseek-*` 后立即出现。
- 原因：主进程对模型 ID 使用 `model.id.startsWith("deepseek-")` 过滤，而设置页文案说明 Base URL 兼容 OpenAI 接口格式。
- 代码：`apps/desktop/src/main/ipc/index.ts` 的 `SETTINGS_LIST_MODELS`
- 处理：已修复。模型列表保留所有合法非空模型 ID；当前 DeepSeek 返回结果和推荐配置不变。未来使用 OpenAI 或其他兼容服务时，后台整理默认跟随会谈模型，不再误用 `deepseek-v4-pro`。

### P2：咨询师资料页底部内容在默认窗口高度下容易被裁切

- 复现：默认 1320 × 860 打开任意咨询师资料页。
- 实际：底部边界说明与预约按钮贴近或落到可视区下沿；无障碍树能找到按钮，但用户肉眼看不到。
- 视觉检查：运行截图 27、28、29。
- 原因：覆盖层是 Grid 子项，却保留默认的自动最小高度；内容较长时面板会超过视口，导致固定操作区也被整体裁切。
- 代码：`apps/desktop/src/renderer/pages/lobby/features/counselors/counselor-introduction.css`
- 处理：已修复。覆盖层允许收缩到视口，正文独立滚动，预约区始终保留在可视底部；主窗口初始尺寸也限制在当前屏幕工作区内。已实机复查默认、最小和全屏三种状态。

### P2：自然长输入和一次超长粘贴未被区分

- 现状：旧发送链路只看最终字符串长度；无论用户自然输入还是一次粘贴，只要超过 20,000 字都会在发送时转成资料，无法满足两种不同意图。
- 处理：已修复。自然输入不限制，也不会自动转换；单次粘贴超过 20,000 字时立即转成可在发送前移除的 `粘贴的长文本.txt`，并显示明确提示。发送纯附件仍可用，空文字且无附件时发送按钮禁用。
- 验证：新增输入与粘贴事件级测试，以及 store 层自然长输入测试；未改上下文预算、截断或模型传输策略。

## 低影响体验与 UI 问题

### P3：新建会谈会直接结束当前未完成会谈，没有就地确认

已修复。侧栏“＋”、桌面菜单与 `Command/Ctrl + N` 现在统一经过同一套前端保护：空会谈可直接替换；存在已发送消息时明确说明当前会谈会结束并进入后台整理；存在未发送文字或附件时明确说明这些内容不会保留，并允许返回检查。后台原子替换、单咨询师仅一条未完成会谈、后台整理和上下文快照逻辑均保持不变。

处理：按用户要求保留现状，等待后续单独设计该页面和引导逻辑。

### P3：空输入时“发送”按钮视觉上仍像可用

没有文字且没有附件时，按钮未禁用；点击后静默无响应。已修复为只禁用发送按钮，输入框和附件按钮保持可用；有待发送附件时仍允许发送。

### P3：使用帮助首次打开默认落在中间主题

全新打开“使用帮助”时默认主题原为“停止、离开与结束”。已改为目录第一项“认识 Ling 和群心心理工作室”，并通过实机界面复查。

### P3：资料桌第 03 本文字对比度偏低

米黄色文字叠在相近的浅米色纸张区域上，标题和正文均比其他资料页更难读。已只加深文字颜色并增加极轻文字阴影，未改构图；实机复查看齐另外两本资料。

### P3：会谈列表中相近记录难以区分

同一咨询师、相近时间创建的当前与历史记录可能同时显示相同截断标题和“刚刚”。已在副标题显示“咨询师 · 进行中/已结束”，并补充列表回归测试。

### P3：空记录页同时出现两层空状态

没有任何会谈时，左侧显示“还没有会谈记录”，右侧同时显示“选择一场会谈”。已合并为跨内容区的单一空状态；全新隔离数据实机复查只出现一层提示。

### P3：测试套件存在 React `act(...)` 警告

原测试会在启动恢复或来信重新生成尚未结束时继续交互，输出异步状态更新未包裹 `act(...)` 的警告。已改为等待真实异步阶段完成；517 个测试全部通过，相关 React 告警已清零，未用 console 屏蔽。

## 上下文、后端和本地数据审查结果

- 会谈流请求校验 `sessionId`，并拒绝请求咨询师/团队与数据库会谈不一致的情况。
- 新会谈在主进程重新生成并冻结咨询师提示词快照，不接受渲染进程带入其他会谈的快照。
- 跨会谈备忘录按咨询师读取，并在新会谈创建时冻结；不会在会谈中途被后台更新替换。
- 短期原文、滚动摘要、基础资料和咨询备忘录分别做预算与截断；审计日志只写 Token 和消息元数据，不写正文。
- 同一会谈的流式请求与状态修改存在互斥协调，停止后额外缓冲片段不会继续写入。
- 备份代码明确删除 `secrets`，隔离数据库恢复后也确认没有 API Key。
- 密码保护保存的是验证值而非明文密码或恢复短语。
- 附件对 txt/md 读取正文；PNG、PDF、DOC/DOCX 等保留为“仅记录附件”，这是当前产品设计，不是解析 Bug。

## 已排除的误报

- 个人资料 1000 字限制有效；自动化工具可绕过原生 `maxLength`，真实键盘输入不可，因此不列为产品 Bug。
- 危机支持第二页卡片是原生可展开 `<details>`；早期自动点击未展开是测试点击目标问题。
- 截图中的大片黑块来自桌面截图差分合成，稳定等待后的完整截图正常，不是 App 渲染问题。
- 模型 Mock 曾返回一次格式错误的测试文案，是本地 Mock 路由匹配错误；修正 Mock 后咨询、流式回复和会谈产物均成功。
- 备份/恢复过程中设置页短暂保留旧 API Key 占位不代表密钥进入备份；数据库与备份代码均已核验排除。
