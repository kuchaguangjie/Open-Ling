# 本地密码与加密规则

Ling 的会谈、来信、记忆和设置默认保存在本机，并由一把本地密码保护。本文件说明这把密码的规则、密钥如何分层、哪些内容受保护、哪些不受保护，以及忘记密码时的处理方式。

面向用户的行为描述见 [PRIVACY.md](../PRIVACY.md)。本文件面向开发者与安全审查，包含实现细节。

## 密码规则

| 项目 | 规则 |
|---|---|
| 字符集 | 纯数字（`0-9`），不区分大小写、不含字母或符号 |
| 长度 | **8 - 64 位** |
| 生效范围 | 仅用于本机解锁与本地数据加密，与任何模型服务商账号无关 |
| 失败限制 | 无尝试次数限制、无递增延迟（见[已知限制](#已知限制)） |

密码只用于解包本机数据密钥，Ling 不保存密码原文，也不把它发送到任何服务器。使用该密码能做的最坏事情是打开这台设备上的本地资料。

### 为什么是纯数字

保持纯数字是为了让解锁输入框可以用系统数字键盘，降低在移动场景下的输入成本。8 位纯数字对应 10⁸ 种组合，配合 `scrypt` 派生，足以抵抗针对 `vault.json` 的离线穷举。

### 历史版本：6 位下限与平滑过渡

2026-09 之前的版本允许 **6 位**数字密码。本次调整把下限提高到 8 位，并按下面的方式平滑过渡：

- **已设置的短密码继续有效。** `validatePin` 只作用于「正在设置的密码」，从不作用于「正在输入的解锁密码」。解锁路径不校验长度，因此老密码仍能正常解开本地资料，无需迁移数据、重写保险箱或改动数据库结构。
- **新密码必须满足 8 位。** 首次设置、用恢复码重设、以及修改密码时，新的密码都必须达到 8 位。
- **应用内提示升级。** 解锁成功后，主进程会根据刚输入的密码长度判断它是否低于当前下限，并通过 `accessLock.status()` 的 `pinUpgradeRecommended` 字段返回给界面。设置页的「解锁密码」区域据此显示一条提示，附「改为 8 位密码」按钮，直接进入既有的修改密码流程。
- **提示会自动消失。** 该标记只在内存中，每次解锁重新推导，不写入磁盘。用户改完密码后，下一次解锁输入的就是 8 位密码，提示自然不再出现。

过渡期间不会锁死任何现有用户，也不会因为升级而要求重新加密数据库。

## 密钥分层

本地数据密钥（data key）是一串 32 字节的随机数，由 `crypto.randomBytes` 生成，与用户密码解耦。密码只用来**包裹**它，因此修改密码不需要重新加密整个数据库。

`userData/security/vault.json` 中存放同一把 data key 的三份包裹（wrapped key），每份都用 `scrypt` 派生密钥 + `AES-256-GCM` 加密：

| 包裹 | 用什么解开 | 用途 |
|---|---|---|
| `password` | 用户设置的 8 位数字密码 | 日常启动解锁 |
| `recovery` | 设置密码时生成的恢复码 | 忘记密码时重设，以及跨设备恢复备份 |
| `device` | 操作系统安全存储 | 「关闭启动密码」后改为设备绑定解锁 |

派生参数为 `scrypt(N=16384, r=8, p=1)`，输出 32 字节；每份包裹使用独立的 16 字节随机盐和 12 字节随机 nonce。

### 恢复码

恢复码由 `createRecoveryPhrase()` 生成：从 32 个易混淆字符（去掉了 `I`、`O`、`0`、`1`）中取 16 个字符，分为 4 组展示。对应 **80 bit 熵**，无法暴力穷举。

- Ling 不保存恢复码原文，只保存它的 `scrypt` 验证值；
- 忘记密码、换新电脑、恢复备份都需要它；
- 输入时会做 NFKC 归一化、去引号、去空白与连字符，因此复制粘贴产生的格式差异不会导致失败。

## 加密范围

### 受保护

| 内容 | 保护方式 |
|---|---|
| 会谈、消息、记忆、资料导入 | SQLCipher 整库加密（`userData/ling.sqlite`） |
| 会谈摘要、概念化、督导、备忘录、来信 | 同上 |
| 设置、模型用量记录 | 同上 |
| API Key 与语音服务凭据 | 操作系统安全存储（Keychain / DPAPI / libsecret），独立文件，**不进入 SQLite** |
| 完整本地备份 `.ling-backup` | SQLCipher 加密，尾部附带恢复码包裹，可用于跨设备恢复 |

数据库与保险箱文件权限为 `0600`，所在目录为 `0700`。备份在写入前会以 `secure_delete` + `VACUUM` 清除 `secrets` 表，因此 **API Key 不会随备份文件离开本机**。

### 不受保护

以下是明确不加密的内容，使用时应自行评估：

- **Markdown 导出（`.md`）**：会谈记录与来信的明文导出，用于阅读和归档，不受本机密码保护。请存放在安全位置。
- **上下文审计日志**：`userData/logs/context-audits/*.json`。仅记录消息 ID、角色、token 统计与预算结果，**不含会谈正文**，但包含会话与消息标识，属于伪匿名元数据。
- **模型服务商侧**：使用远程模型时，完成功能所需的 Prompt、消息与受预算控制的上下文会发送给用户选择的服务商，按其规则保存。使用本机模型时内容不离开设备。

## 免密窗口

解锁后，data key 会用操作系统安全存储加密写入 `userData/security/grace-session.json`，并带一个有效期。在有效期内重新打开 Ling 无需再次输入密码。

可选值为 **0（每次验证）/ 5 / 15 / 30 分钟**，默认 5 分钟。选择「立即锁定」或主动锁定会立刻清除该文件。

这只是便利性取舍：它不会关闭密码保护，也不会让数据库变成未加密。如果设备可能被他人接触，建议设为 0。

## 忘记密码怎么办

1. 在解锁界面选择「忘记密码」，输入恢复码；
2. 验证通过后设置一个新的 8 位以上密码；
3. 保险箱中的 `password` 包裹会被替换，data key 不变，因此**数据不会丢失也不需要重新加密**。

如果恢复码也丢失，本地数据无法恢复。Ling 不保存密码或恢复码的可读形式，也没有服务端可以帮忙重置。

## 已知限制

- **解锁没有失败次数限制。** 拿到 `vault.json` 的攻击者可以离线穷举密码，每次尝试只需一次 `scrypt`。这正是下限提高到 8 位的原因；进一步的缓解（失败计数、递增延迟、提高 `scrypt` 参数）尚未实现。
- **短密码仍然可用。** 过渡期内老用户的短密码依然有效，直到他们主动修改。
- **设备绑定等同 OS 账号安全。** 「关闭启动密码」或免密窗口下，能登录该操作系统账号的人即可打开本地资料。
