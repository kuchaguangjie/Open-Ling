# Ling 专业咨询师扩展开发规范

## 1. 定位与责任

Ling 咨询师包不是普通角色卡或娱乐性 Agent。咨询师的人格、理论取向、关系定位和正式 Prompt 应由具备相应心理咨询知识与实践判断能力的专业人员或机构设计、审阅和持续迭代。

发布者对包内的专业内容、适用范围、权利声明和版本质量负责。通过 Ling 的技术校验，只表示包结构、资源路径、引擎版本和系统安全基线兼容，不表示 Ling 已核验发布者资质、认可其专业主张或承诺咨询效果。

不得将未经专业审阅的自动生成 Prompt 包装为专业心理咨询师，不得承诺治疗效果，也不得通过人格设定制造权威依赖、排他关系或替用户作出重要决定。

## 2. 开发与发布边界

专业开发工程可以在私有仓库或内部目录中保存候选 Prompt、迭代记录、安全测试、评测数据和反馈分析。正式咨询师包只能包含经过确认的发布内容。

```text
专业开发工程（不分发）
├── Prompt 候选稿与迭代记录
├── 专业评审与安全测试
├── 测试对话、评测数据与反馈分析
└── 正式发布内容

正式咨询师包（可导入）
├── manifest.json
├── prompts/
└── assets/
```

Ling 导入时只复制 `manifest.json` 明确声明的 Prompt 和图片。未声明的候选稿、测试文件和附带资料不会进入应用管理目录。

## 3. 标准目录

```text
counselor-package/
├── manifest.json
├── prompts/
│   ├── core-zh.md
│   ├── core-en.md
│   ├── dialogue-zh.md
│   ├── dialogue-en.md
│   ├── voice-zh.md          # 可选
│   └── voice-en.md          # 可选
├── policies/                # 可选，只能追加安全约束
│   └── additional.md
└── assets/
    ├── avatar.png
    ├── portrait.png
    └── room.png
```

可以使用下列命令生成标准示例目录。该命令只生成结构和中立占位内容，不会生成可直接发布的专业咨询师 Prompt。

```bash
npm run counselor:create -- ./my-counselor my-counselor
```

## 4. Manifest 必填信息

- `schemaVersion`：当前为 `1`。
- `id`：稳定且全局唯一的小写标识；发布后不要因名称调整而修改。
- `version`：语义版本，例如 `1.2.0`。
- `engineCompatibility`：支持的 Ling 咨询师引擎范围，例如 `>=1.0.0 <2.0.0`。
- `publisher`：实际承担发布责任的个人或机构名称，可附官方网站。
- `license`：分别声明正式 Prompt 与图片资源的许可证。
- `approach`：咨询师的主要理论取向。
- `localizations`：中英文名称、介绍、擅长方向、开场语和结束语。
- `prompts`：中英文核心 Prompt、实时会谈 Prompt，以及可选的中英文语言风格 Prompt。
- `safety`：最低安全规则版本和只能追加、不能替代系统基线的规则。
- `visuals`：头像、立绘、咨询室以及可选开场/结束序列。

完整字段和资源格式见 [咨询师包技术说明](./counselor-packages.md)。

同一咨询师持续迭代时必须保持 `id` 不变并提高 `version`。Ling 只接受严格高于当前版本的更新；不要通过更换 `id` 规避版本管理，否则会把同一咨询关系拆成两位不同咨询师。旧会谈会保留创建时冻结的 Prompt，新会谈才使用新版。

## 5. 专业人员可定义的范围

- 咨询师名称、形象、人格和关系定位；
- 理论取向、概念理解方式和会谈工作方式；
- 核心 Prompt 与实时会谈 Prompt；
- 可选的独立语言风格 Prompt，用于表达节奏、句式和语气，不承载理论核心或系统安全规则；
- 语言风格、回应节奏、提问和澄清方式；
- 擅长议题、适用范围和明确的不适用范围；
- 开场语、结束语和附加安全约束；
- 中英文内容、版本、发布者和资源许可证。

## 6. 由 Ling 固定提供的范围

咨询师包不得声明、关闭、替换或削弱以下能力：

- 共享咨询价值、咨询伦理、实时安全基线与风险路由；
- Memory 基础设施、用户隐私设置、上下文顺序和跨会谈资料注入规则；
- 面向不同模型的 Prompt 编译、推理参数和采样策略；
- 个案概念化与长期概念化；
- 李燕云督导；
- 咨询备忘录和会谈来信；
- 本地数据库、模型密钥和用户文件访问边界。

咨询师包不执行 JavaScript 或其他代码，也不获得数据库、密钥和用户文件访问权。

## 7. 当前会谈上下文契约

Ling 使用版本化的会谈快照和模型运行契约。扩展作者需要明确哪些内容由包定义，哪些内容由宿主实时提供：

```text
创建会谈时冻结
├── 咨询师核心 Prompt
├── Ling 共享咨询价值
├── 实时会谈场景 Prompt
├── 可选语言风格 Prompt
├── 语言、咨询师包版本与内容哈希
└── 模型能力、Prompt 编译器与采样契约

每次请求时由 Ling 组装
├── 冻结的会谈快照
├── 当前咨询伦理与实时安全规则
├── 基础资料（受独立预算控制）
├── 较早会谈的 rolling summary（需要时）
├── 上一周期冻结的咨询备忘录（用户启用连续性时）
└── token 预算内的近期逐字消息
```

咨询师包只拥有 `counselorCore`、`counselingDialogue`、可选 `counselorVoice` 和只能加强约束的 `additionalPolicies`。它不能指定消息角色、改变上下文顺序、选择 Prompt 编译器、注入任意会谈记忆，或直接控制供应商请求参数。

会谈创建后，包升级不会改变该会谈已经冻结的 Prompt；新会谈才使用新版。咨询伦理和实时安全规则不冻结在扩展快照中，而是由 Ling 在每次请求时使用当前版本重新注入。这样既保持咨询关系的一致性，也允许系统安全边界持续修正。

## 8. Prompt 编写要求

正式 Prompt 至少应明确：

- 咨询师如何理解自己的角色和能力边界；
- 如何建立尊重、自主、可修正的咨询关系；
- 理论取向如何影响倾听、理解和回应，而不是机械套用术语；
- 如何避免过度解释、过早建议、诊断化表达和替用户决策；
- 如何处理不确定、误解、沉默、抵抗和关系张力；
- 如何与 Ling 的统一安全规则协作；
- 如何避免依赖诱导、排他性承诺和对现实专业支持的贬低。

附加安全规则只能提高约束，不能要求忽略或覆盖 Ling 系统安全基线。

核心 Prompt 应集中描述身份、关系立场、理论取向与稳定工作原则；实时会谈 Prompt 应集中描述如何处理当前表达、形成暂时理解并把理解带回对话；语言风格 Prompt 只负责表达层。不要在三个文件之间复制同一整套规则，也不要依赖 Manifest 中没有声明的附带文件。

## 9. 发布前专业检查

- [ ] 正式 Prompt 已由具备相应专业能力的人员审阅；
- [ ] 人格、理论取向和实际回应方式保持一致；
- [ ] 完成多轮、长上下文和跨会谈测试；
- [ ] 在至少一个普通 chat 模型和一个 reasoning 模型上验证回应，未依赖特定消息位置或供应商私有参数；
- [ ] 覆盖自伤、他伤、虐待、妄想、依赖等高风险情境，以及需要额外支持的使用者的安全需求；
- [ ] 不承诺治疗效果，不制造权威依赖或排他关系；
- [ ] 不替用户作出医疗、法律、财务或重大人生决定；
- [ ] 明确适用范围、不适用范围和 AI 咨询边界；
- [ ] Prompt、图片、名称和形象拥有可分发权利；
- [ ] 包内没有候选稿、测试记录、评测数据、真实会谈或用户反馈；
- [ ] 中英文内容、版本、发布者和许可证信息完整；
- [ ] 已在 Ling 中完成导入预览和真实会谈流程验证；
- [ ] 已验证概念化、督导、备忘录和来信能够正常生成。
- [ ] 升级测试确认新会谈使用新版本，旧会谈仍保持原有 Prompt 快照。

## 10. 来源标识

- `Ling 官方`：由上海啸群教育科技有限公司发布并随 Ling 提供。
- `合作开发`：仅用于 Ling 已完成合作确认和专业审核的发行物，不能由第三方在 Manifest 中自行声明。
- `本地导入`：用户从本机选择的包。通过技术校验不等于经过 Ling 专业审核。

当前公开版本提供本地导入，不提供开放上架、热度排名或娱乐化评分市场。未来如提供合作咨询师目录，也应采用审核制的专业资源目录，而不是自由上架的 Agent 市场。
